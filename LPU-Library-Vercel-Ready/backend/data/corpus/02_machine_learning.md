## Core concepts

A learner should begin by defining the problem and identifying the inputs, outputs, constraints, and success criteria. Build a mental model before memorizing terminology. For each concept, write what it means, why it is useful, when it should be applied, and one situation where it may fail. In Machine Learning, these foundations help students distinguish similar techniques and select an appropriate solution.

## Practical workflow

A repeatable workflow is: (1) understand the task and available data, (2) identify the simplest valid approach, (3) implement a small baseline, (4) test normal and edge cases, (5) measure correctness and efficiency, and (6) document assumptions and limitations. For software and data projects, keep inputs validated, secrets outside source code, and persistent information in an appropriate managed store.

## Example and interpretation

Consider a student project that must organize information and answer questions. The system should represent each item with clear metadata, transform source material into searchable units, retrieve relevant evidence, and produce an explanation tied to that evidence. A result is not reliable merely because it sounds fluent: the supporting material must actually contain the claimed facts. If evidence is missing, the system should say that it cannot verify the answer.

## Common mistakes

Common mistakes include confusing correlation with causation, choosing a complex method before establishing a baseline, ignoring data quality, evaluating only on training examples, overlooking edge cases, and presenting illustrative records as real institutional data. Another frequent mistake is treating a successful API response as proof of correctness. Test retrieval quality, output quality, source attribution, latency, and failure handling separately.

5. What evidence would you show to justify the final answer?
